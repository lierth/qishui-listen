# 汽水音乐 · 自动刷广告领畅听时长

Hamibot 脚本。自动完成：**打开 App → 我的 → 更多 → 领取 → 看广告 → 关广告 → 领奖励 → 循环**，直到今天奖励次数达到上限。

|---|---|

| [hamibot.config.json](hamibot.config.json) | Hamibot 项目配置 |
| [config.json](config.json) | 包名等配置 |

## 怎么用

1. 手机装好 Hamibot，开启无障碍（设置 → 无障碍 → Hamibot）。
2. Hamibot 里新建脚本，把 [index.js](index.js) 全部内容粘进去。
3. 点运行。脚本自己会打开汽水音乐，跑到「我的 → 更多 → 领取」，然后循环刷广告。
4. 到上限自己停（判定依据见下）。

## 换手机为什么也能用

这是这次重点改的地方。旧脚本的问题是坐标写死，换台手机就点空。

**三条原则：**

1. **语义优先**。能靠 `content-desc` / `text` / `resource-id` 找到的，一律不写坐标。
   - 领取按钮：`领时长` / `继续领` / `领取`
   - 广告倒计时：`15秒后可领取奖励`
   - 奖励弹窗：`领取奖励` / `坚持退出`
   - 换手机文案不变，所以定位不变。

2. **比例兜底**。只有「更多」这个齿轮图标没有任何文字，才用比例：
   - 坐标 = `device.width * 0.93`、`device.height * 0.083`
   - 实测在 720×1600 到 1440×3200 之间落点都正确。

3. **点完必须验**。每次点击都检查界面**真的变了**，没变就换方案，绝不空转。

## 这次实测确认的关键结论

### 1. 关闭广告要点 X 图标，不是文字

广告右上角 `领取成功，关闭，按钮` 的可点区域是：
- 容器 `[891,153][1168,257]`
- 里面那颗小 `ImageView` `[1101,192][1127,218]` ← **必须点这里**（中心 1114,205）

点文字中心（1029,205）**点不动**。旧脚本死循环就是卡在这。

脚本里的处理顺序：子 ImageView → 兄弟 ImageView → 容器右端内缩 4.5% 屏宽。

### 2. 怎么判断「今天满了」

**弹窗标题变成「明日免费听」就是满了**。这是最可靠的信号：

| 标题 | 含义 |
|---|---|
| `今日免费听` | 今天还没满，继续 |
| `第6日免费听` | 连续签到第 6 天，继续 |
| `明日免费听` | **今天已满，收工** |

旧脚本没有这个判断，会一直刷到天亮。

### 3. 满了之后还会进广告页（现在能处理）

今天满了再点「继续领」，仍然会进一个**没有倒计时、直接显示「领取成功」**的广告位。

如果只看「领取成功」就点关闭，会无限空转 —— 这也是旧脚本失效的原因之一。现在的处理：认出「明日免费听」直接退出，不进去。

### 4. 播放页的搜索图标会冒充「更多」

「我的」页右上角 `\ue8a8`（更多）和播放页右上角 `\ue63d`（搜索）**位置几乎完全一样**：

```
我的页   [1083,170][1187,274]   \ue8a8
播放页   [1064,168][1168,275]   \ue63d
```

纯按位置判断会点成搜索。脚本改成**按字形精确匹配** `\ue8a8`，位置兜底只在确认是「我的」页时才启用。

### 5. 抽屉里的「清理缓存 >」会冒充关闭按钮

抽屉项右侧有箭头，描述里带「关闭」语义，会被误认成广告 X。脚本加了双重限制：
- 只在**广告页**才找关闭按钮
- 关闭按钮必须位于**屏高顶部 15%** 内

### 6. 直播间广告的 Activity 完全不一样（实测新增）

正常激励视频是 `ExcitingVideoActivity`，但**直播间广告**用的是：

| Activity | 说明 |
|---|---|
| `com.bytedance.mira.stub.p0.StubTranslucentActivity` | 直播间外壳（最常见） |
| `com.luna.biz.live.plugin.LunaSmoothLivePlayerActivity` | 直播间播放器 |

只认 `ExcitingVideo` 的话，进直播间会被误判成「已回到主界面」，**广告阶段提前结束**。现在统一用 `onAdActivity()` 判断。

### 7. 直播间取不到任何节点 → 只能盲关

直播间由 `SurfaceView` 渲染，`uiautomator dump` **一个节点都拿不到**。所以：

- 靠 Activity 名识别
- 按比例盲点右上角 X：**(0.943, 0.084)**（实测命中）
- 多个候选比例兜底

### 8. 退出直播间有三层挽留

点 X 之后不是直接退出，而是「为你精选以下直播」页：

1. 页面底部有 **「退出不看了」** ← 必须点这个
2. 中间大按钮「浏览更多直播」是陷阱，点了反而进新直播
3. 还有「换一个」之类的干扰

脚本的 `exitLiveRoom()` 专门点「退出不看了 / 狠心离开 / 不看了」这类词。

### 9. `StubTranslucentActivity` 会被误判为已回主界面

这是最隐蔽的一个。`StubTranslucent` 上没有广告栏元素时，
如果只判断「不在 ExcitingVideo 上 = 回主界面了」，就会提前终止整轮。

### 10. 弹窗会正常重复出现，不能当卡死

实测进度是 **第7日 → 第8日 → …** 逐天推进的。同一轮里「领取奖励」弹窗会出现多次，
`再看2个` → `再看1个` 提示也在变。

所以卡死判定要满足：**天数标题 + 剩余提示都没变，连续 5 次**，才认定卡死。
次数设小了会把正常流程误杀。

## 自愈能力

| 情况 | 处理 |
|---|---|
| App 没开 / 被杀 | 重新拉起 |
| 停在上一个广告 | 返回后重新进 |
| 误入播放页 / 搜索页 / 金币页 | 自动返回 |
| 权限 / 升级弹窗 | 自动点「允许」「以后再说」 |
| 卡在同一状态 | 计数后退出重来 |
| 开屏广告 | 自动点「跳过」 |
| **直播间广告（无节点）** | Activity 识别 + 比例盲关 X |
| **退出直播间的挽留页** | 自动点「退出不看了」 |
| **单轮内抛异常** | 整轮 try/catch，不中断整个脚本 |
| **弹窗点了没用** | 换位置重点 → 坚持退出 → 强制返回 |

## 可调参数

在 [index.js](index.js) 顶部 `CFG` 里：

```js
MAX_ADS: 80,          // 单次最多看多少支广告（保险丝）
MAX_MINUTES: 150,     // 单次最长运行分钟数
AD_WAIT_MAX_MS: 65000,// 单支广告最长等待
CLOSE_RETRY: 6,       // 每支广告关闭重试次数
DEBUG: true           // 关掉可以减少日志
```

## 已知限制

- 汽水音乐改版换了文案，脚本需要跟着改 `CLAIM_TEXTS` 等常量。
- 广告页若用纯 SurfaceView 绘制、无障碍取不到节点，只能靠顶部栏特征兜底。
- 页面持续动画时 `uiautomator dump` 可能报 `could not get idle state`，这是 adb 工具的限制，不影响 Hamibot（走无障碍事件）。
- 只在小米 17 Pro（1220×2656 / Android 17）上实测；其他机型靠比例+语义适配，建议首次运行看一遍日志。
- 直播间盲关的比例 (0.943, 0.084) 是按 1220×2656 实测的，其他分辨率靠比例换算，若关不掉会依次尝试 4 个候选点。
