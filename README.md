# 汽水音乐任务自动化脚本

这是一个基于 Hamibot / Auto.js 的 Android 自动化脚本，用来验证移动端 App 任务流程的自动化能力。脚本以汽水音乐的「我的」页任务入口为示例，自动完成进入任务、等待广告、关闭广告、领取奖励和状态恢复等步骤。

项目重点是把一个真实 App 中经常变化的任务流程拆成可执行的自动化逻辑：通过控件文本识别主要入口，通过相对坐标处理广告页关闭，通过状态判断处理连续奖励、退出确认和任务完成。

## 分支说明

本项目采用以下分支策略，方便管理和使用：

| 分支 | 说明 |
|------|------|
| `main` | 最新版本的稳定版，始终代表当前最可靠的代码。 |
| `dev` | 开发分支，新功能和修复先在此分支验证，稳定后再合并到 `main`。 |
| `main-x.x.x` 等版本分支 | 仅按汽水音乐版本区分的稳定版脚本，如 `main-21.1.0` 分支仅适配汽水音乐 21.1.0 版本。 |
| `main-设备型号-x.x.x` | 按**设备型号 + 汽水音乐版本**区分的稳定版脚本。例如 `main-xiaomi-17-pro-21.1.0` 表示：正式版 (`main`) + 小米 17 Pro (`xiaomi-17-pro`) + 汽水音乐 21.1.0 (`21.1.0`)。该分支仅适配此特定设备与版本组合，其他设备或版本可能需自行校准坐标。 |

建议根据你安装的汽水音乐版本（以及设备型号）选择对应分支；如果不确定，优先使用 `main` 分支。

## 功能特性

- 自动等待 Hamibot 无障碍服务启动（带重试，服务被系统解绑也不会直接退出）；
- 启动汽水音乐并自动回到「我的」页面；
- 识别「领时长」「继续领」等任务入口并开始任务；
- 按倒计时控件精确等待，而不是盲等固定时长；
- 通过「反馈」控件或右上角 X 图标的真实坐标关闭广告页；
- 检测「领取奖励」并支持连续广告任务；
- 关闭广告后仍停留在广告奖励页时，自动识别并继续下一轮；
- 检测「坚持退出」并完成退出确认；
- 检测直播间广告（含无节点场景）并自动退出，逐层点掉挽留页；
- 检测到「明日免费听」判定今日奖励已达上限，自动结束并返回；
- 单轮异常自动重试，找不到入口时自动纠偏，避免脚本卡死。

## 实现思路

脚本运行后会先确认无障碍服务是否就绪，然后打开汽水音乐。如果当前不在「我的」页，会点击底部标签；如果误入播放页、搜索页或金币页，会自动返回。

进入「我的」页后，点右上角「更多」打开侧边抽屉，在抽屉里找到「领时长」或「继续领」按钮，点击进入广告任务。随后进入广告处理流程：读取倒计时秒数并等待，广告结束后关闭，再判断是否出现奖励弹窗。如果出现「领取奖励」，继续下一轮；如果弹窗标题变成「明日免费听」，说明今日次数已满，点「坚持退出」收工。

```text
启动脚本
  ↓
等待无障碍服务就绪
  ↓
打开汽水音乐 → 回到「我的」页
  ↓
点「更多」打开侧边抽屉
  ↓
查找「领时长 / 继续领」并点击
  ↓
读取倒计时并等待广告播完
  ↓
关闭广告（含直播间盲关）
  ↓
判断领取奖励 / 明日免费听 / 坚持退出
  ↓
继续下一轮或结束脚本
```

## 跨设备适配说明

这是本项目与常见方案最大的不同点。旧的写法把坐标写死，换一台手机就点空，所以这里做了三层设计：

**第一层：语义定位优先。** 凡是能用 `content-desc`、`text`、`resource-id` 找到的元素，一律不写坐标。

| 元素 | 定位方式 |
|------|----------|
| 领取按钮 | 文案 `领时长` / `继续领` / `领取` |
| 广告倒计时 | `15秒后可领取奖励` 正则提取秒数 |
| 奖励弹窗 | `领取奖励` / `坚持退出` |
| 底部我的 | `resource-id = navigation_tab_me` |

**第二层：比例兜底。** 只有「更多」这个齿轮图标没有任何文字（是字体图标 `\ue8a8`），才使用屏幕比例：

```javascript
点击位置 = (device.width * 0.930, device.height * 0.083)
```

实测在 720×1600 到 1440×3200 的区间内落点都正确。

**第三层：点完必须验。** 每次点击后都检查界面是否真的发生了变化，没变化就换方案，绝不空转。

1. 在 Android 设备上安装并配置 Hamibot。

2. 将 `index.js` 中的代码复制到 Hamibot 脚本源码中。

3. 确认已授权无障碍服务，并按需授予截图或悬浮窗等运行权限。

4. 在 Hamibot 中运行脚本。

```bash

node test/simulate.js   # 73 项：全流程 + 换机 + 直播间 + 盲点 + 卡死自愈 + 重启
```

两套共 **101 项，全部通过**。测试用真机抓下来的界面快照作为 fixture，不依赖手机也能回归。

## 实测踩过的坑

以下是真机调试中确认的问题，也是脚本里那些"看起来多余"的判断的由来。

### 关闭广告要点 X 图标，不是文字

广告栏 `领取成功，关闭，按钮` 的实际可点区域是容器里那颗小 `ImageView`：

```
容器    [891,153][1168,257]
文字中心 (1029,205)   ← 点这里没反应
X 图标   (1114,205)   ← 必须点这里
```

脚本的取值顺序：子 `ImageView` → 兄弟 `ImageView` → 容器右端内缩 4.5% 屏宽。

### 「明日免费听」才是上限信号

| 弹窗标题 | 含义 |
|----------|------|
| `今日免费听` | 今天还没满，继续 |
| `第6日免费听` | 连续签到第 N 天，继续 |
| `明日免费听` | **今天已满，收工** |

没有这个判断会一直刷到天亮。

### 满了之后仍会进广告页

今天满了再点「继续领」，依然会进一个没有倒计时、直接显示「领取成功」的广告位。只看「领取成功」就点关闭，会无限空转。

### 播放页的搜索图标会冒充「更多」

```
我的页   [1083,170][1187,274]   \ue8a8  ← 更多
播放页   [1064,168][1168,275]   \ue63d  ← 搜索
```

位置几乎完全重合，纯按位置判断会点成搜索页。脚本改成按字形精确匹配 `\ue8a8`，位置兜底只在确认处于「我的」页时才启用。

### 抽屉里的「清理缓存 >」会冒充关闭按钮

抽屉项右侧箭头带「关闭」语义，会被误认成广告 X。脚本加了双重限制：只在广告页才找关闭按钮，且必须位于屏高顶部 15% 内。

### 直播间广告的 Activity 完全不同

| Activity | 场景 |
|----------|------|
| `ExcitingVideoActivity` | 普通激励视频 |
| `StubTranslucentActivity` | 直播间外壳（最常见） |
| `LunaSmoothLivePlayerActivity` | 直播间播放器 |

只认 `ExcitingVideo` 会把直播间误判成「已回到主界面」，导致整轮提前结束。

### 直播间有两种形态，都要处理

| 形态 | 节点情况 | 关闭方式 |
|------|----------|----------|
| 正片 | 有 314 个节点，含可点 `关闭` Button `[1090,176][1207,293]` | 直接点节点（更可靠） |
| SurfaceView 渲染 | `nodes: 0`，一无所有 | 按比例盲关 |

```javascript
// 兜底盲关坐标
点击位置 = (device.width * 0.943, device.height * 0.084)
```

只按「读不到节点」判断会**漏掉有节点的正片形态**，所以识别以 Activity 名为主，
内容特征仅作辅助。

### 退出直播间有三层挽留

点 X 不会直接退出，而是弹出「为你精选以下直播」：

- 底部 **「退出不看了」** ← 必须点这个
- 中间大按钮「浏览更多直播」是陷阱，点了反而进新直播间

### 奖励弹窗有时完全读不到节点

屏幕上明明显示 `再看2个视频提前得 / 第13日免费听 / 领取奖励 / 坚持退出`，但无障碍树里这几个节点**一个都读不到**：

```
读得到的:  '反馈，按钮'  '领取成功，关闭，按钮'
读不到的:  '领取奖励'    '坚持退出'    '第13日免费听'
```

后果是脚本以为还在放广告，一直点 X；点多次无效改按 `back()`，而**广告页里 `back()` 也退不出去**（实测连按 5 次仍在原页），最终归位失败、整轮报错。

解法是盲点比例坐标：

- `领取奖励` ≈ `(0.500, 0.534)`
- `坚持退出` ≈ `(0.500, 0.600)`

但盲点有风险：直播落地页的节点签名和它几乎一样（都只有 `反馈` + `领取成功`），在落地页上盲点会误触「点击进入直播间」。所以盲点**必须带卡住证据**——同一关闭按钮连点 2 次无效才允许。

### 点 X 无效时要「就地盲点」，不能先 back

这是一个顺序 bug。原来的写法是：

```
点 X 5 次无效 → back() + continue   ← 盲点逻辑还没执行就到下一轮了
```

`closeTries` 在「关闭广告」那一段才赋值，而盲点判断在它之前，
所以 **`closeTries` 永远是 0，盲点永远不触发**，只在原地空转。

现在改成：点 X 无效 **2 次**就就地盲点「领取奖励」，成功才继续，
3 次还不行才盲点「坚持退出」脱身。盲点候选点按实测的红色按钮范围
（y=1386~1528）覆盖上下沿。



### 遇到脏状态就彻底重启，不要在原地猜

实测遇到的"未知状态"太多了：停在广告页、弹窗读不到节点、
`back()` 退不出去、误入系统设置页、直播间无节点……
逐个打补丁成本越来越高，而且容易越陷越深。

所以加了一条兜底策略 —— **系统性杀掉重启**：

```text
openAppSetting(com.luna.music)
  ↓
应用信息页 → 点「结束运行」
  ↓
点「确定」
  ↓
回桌面 → 冷启动 → 干净的起点
```

实测 `ps` 确认进程真的归零，再启动就是全新状态。触发条件：

| 位置 | 阈值 |
|------|------|
| `ensureDrawerReady` 归位 | 连续失败 3 次 |
| 主循环 | 连续 2 轮未推进（之后每 2 轮一次） |
| 主循环抛异常 | 同上 |

全部靠文案定位（`结束运行` / `强行停止` / `确定`），不依赖像素。

### 点击屏幕中央会点中小米悬浮球

日志里如果出现连续多行 `[更多] 比例兜底 ...` 加 `[归位] 第 N 次失败`，
说明脚本已经**不在汽水音乐里**了。实测原因是：

```
tapRatio(0.5, 0.5)   ← 想"点掉遮罩"，结果点中了屏幕左边缘的悬浮球
→ 被带到 com.miui.touchassistant 设置页
→ 脚本在里面反复找「更多」按钮，永远失败
```

小米/红米设备的悬浮球是系统级 overlay，会吃掉点击。修复：
- 删掉所有"盲点屏幕中央"的动作；
- `curPkg() != com.luna.music` 时，**先按返回退出**（实测 1~2 次即可），
  再拉起汽水音乐，而不是直接 `launchApp`。

### 盲点坐标要以「节点框」为准，不是色块

一开始按红色色块的上下沿（y=1386~1528）量盲点位置，后来拿到弹窗
可读时的真实节点才发现框是 `[514,1383][706,1452]`——**色块比可点区域大**，
落在色块边缘不会触发点击。

| 元素 | 真实节点框 | 中心 | 比例 |
|------|-----------|------|------|
| 领取奖励 | `[514,1383][706,1452]` | (610,1417) | (0.500, 0.534) |
| 坚持退出 | `[518,1564][702,1625]` | (610,1594) | (0.500, 0.600) |

另外发现：弹窗读不到节点，有时是 **Hamibot 自己的日志浮窗盖住了**。
浮窗关掉后节点就正常可读，此时走语义定位比盲点更准。

### 弹窗会正常重复出现，不能当卡死

实测进度是逐天推进的（`第7日 → 第8日 → …`），同一轮里「领取奖励」弹窗会出现多次，`再看2个` → `再看1个` 提示也在变。所以卡死判定必须满足「天数标题 + 剩余提示都没变，且连续多次」，阈值设小了会把正常流程误杀。

## 自愈能力

| 情况 | 处理 |
|------|------|
| App 没开 / 被杀 | 重新拉起 |
| 停在上一个广告 | 退出后重新进 |
| 误入播放页 / 搜索页 / 金币页 | 自动返回 |
| 权限 / 升级弹窗 | 自动点「允许」「以后再说」 |
| 开屏广告 | 自动点「跳过」 |
| 直播间广告（无节点） | Activity 识别 + 比例盲关 X |
| 退出直播间的挽留页 | 自动点「退出不看了」 |
| 弹窗读不到节点 | 带证据盲点比例坐标 |
| `back()` 退不出广告页 | 盲点坚持退出 → 多次 back → 回桌面重开 App |
| 单轮抛异常 | 整轮 try/catch，不中断整个脚本 |

## 可调参数

在 `index.js` 顶部 `CFG` 里：

```javascript
MAX_ADS: 80,           // 单次最多刷多少支广告（保险丝）
MAX_MINUTES: 150,      // 单次最长运行分钟数
AD_WAIT_MAX_MS: 65000, // 单支广告最长等待
CLOSE_RETRY: 6,        // 每支广告关闭重试次数
DEBUG: true            // 关掉可减少日志输出
```
